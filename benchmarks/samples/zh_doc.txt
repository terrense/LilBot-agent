# LilBot 运行时架构说明

本文用一个完整回合说明 LilBot 的执行路径、上下文管理和失败恢复。目标读者是准备接手维护的工程师，因此只讲真实代码里存在的结构，不讲愿景。

## 1. 一次回合做了什么

用户输入进入 `Agent.run_turn()` 后，依次发生：

1. 追加一条 `role=user` 消息，并写入 SQLite 会话库。
2. 触发 `user_prompt_submit` 和 `turn_start` hooks。
3. 按 token 预算检查是否需要压缩历史。
4. 启动记忆召回的后台侧查询，不阻塞主模型。
5. 进入 while 循环：调用 Provider、读取流式文本、收集工具调用。
6. 把工具调用按并发安全性分批执行，结果作为 `role=tool` 消息回灌。
7. 没有工具调用时结束回合，持久化并触发 `turn_end`。
8. 步数超限时用已有证据强制收敛，而不是无限重试。

主循环只产出事件，UI 只消费事件。新增入口（HTTP API、网关、评测 adapter）可以复用同一个循环，不需要复制业务逻辑。

## 2. Provider 层

`llm/providers.py` 定义 `BaseProvider`，并提供两种实现：

- `OpenAICompatibleProvider`：同步请求和 SSE 流式两种传输，复用一条 keep-alive HTTP 客户端，支持 DeepSeek、OpenAI、OpenRouter、Ollama、vLLM、LM Studio 等端点。
- `RuleBasedProvider`：离线规则桩，不联网、不需要 Key，用于测试和演示。

Provider 错误会被分类成认证、限流、超时、上下文溢出等类别，重试循环据此决定退避、重试还是降级。上下文溢出和输出截断有独立的恢复路径，不与普通网络错误混在一起。

## 3. 工具契约

每个工具是一个 `ToolDef`，声明：

- 名称、描述、JSON Schema；
- 能力集合（读、写、网络、执行等）；
- 审批级别；
- `validateInput`：执行前校验，给模型可读的失败原因；
- `isConcurrencySafe` / `isDestructive`：逐输入判定；
- `maxResultSizeChars`：输出上限，超过则落盘并回传预览；
- `should_defer` / `searchHint`：延迟加载和检索提示；
- `contextModifier`：执行后以纯函数方式改写后续上下文。

权限由 `ToolRegistry.execute()` 统一收口。工具 handler 不再各自实现审批，新增工具也不能悄悄绕过权限门。

## 4. 上下文管理

上下文按“便宜到昂贵”分层：

1. L0 工具结果预算：把过大的旧工具结果替换成预览，完整内容留在磁盘。
2. 缓存感知裁剪：只改还没进入 Provider 缓存前缀的内容。
3. 结构化摘要：把较早的对话压缩成带固定段落的 handoff 文档。
4. 会话记忆：后台维护一份结构化笔记，跨压缩保留。
5. 反应式恢复：真正遇到溢出时才触发压缩并重试，且有次数上限和熔断。

token 计数优先使用 Provider 回报的真实 usage，字符估算只做兜底。中文、日文、韩文按字符类别单独估算，再用品 Provider 的真实值校准。

## 5. 子代理与团队

`SubAgentManager` 内置 11 种角色：general、explore、researcher、plan、review、writer、critic、implementer、verifier、tool_agent、custom。角色可以来自内置定义，也可以来自 `.lilbot/agents/*.md` 的 frontmatter。

子代理有工具白名单、并发上限、JSONL transcript、任务落盘重启恢复和可选的 git worktree 隔离。团队层提供文件信箱和共享任务看板，成员是进程内线程，不是分布式服务。

## 6. 安全边界

- 权限模式：ask、accept-all、deny-all。
- 规则语法：`Tool(pattern)`，按 policy、project、user 分层，deny 优先于 ask，ask 优先于 allow。
- Shell：灾难命令先拒绝；已知只读命令用 arity 感知前缀匹配；PowerShell 再做令牌级风险分析。
- 密钥：模型发起的子进程默认剥离密钥类环境变量；读取密钥或 `.env` 的命令不会自动放行；工具输出回灌模型前替换已知密钥原值。
- 沙箱：路径必须落在 workspace 内，但它不是 OS 级隔离。跑不可信代码时应在外面再加容器或虚拟机。

## 7. 持久化与恢复

会话消息在追加时写入 SQLite，而不是只在回合结束时写 JSON。这样进程中途被杀，已经发生的工具结果和消息不会全部丢失。文件编辑前有快照，支持 `/rewind` 回滚文件；Shell 和网络副作用不在回滚范围内，文档必须把这一点讲清楚。

事件日志 `.lilbot/events.jsonl` 是追加写的结构化日志，用于分析成功率和坏例，不是权威状态源。恢复以会话库和磁盘状态为准。

## 8. 评测

评测分两层：

- mock 层：把模型决策写成受控输入，测运行时行为，完全离线。
- live 层：真实模型跑 24 个 trial，记录 JSONL trace、工具名、参数、结果状态、延迟和 token 用量。

评分器检查工具是否成功、最终答案是否包含目标文本、产物是否存在、权限是否被正确拒绝。失败用例连同 trace 一起发布，用于回归和坏例分析，而不是只公布一个成功率。
