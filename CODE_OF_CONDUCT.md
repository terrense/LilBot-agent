# Code of conduct

LilBot is a small project. The standard is simple: be respectful, argue about
the work, and do not make the project hostile to people who are trying to help.

## Expected behavior

- Assume good faith. Ask a question before assuming a mistake was careless.
- Critique the change, the evidence, or the design — not the person.
- Keep reviews specific and actionable. "This fails when X because Y" is better
  than "this is bad".
- Respect different experience levels. A clear explanation is more useful than
  a terse dismissal.
- Accept a maintainer's decision once it is made, even if you disagree. You can
  ask for the reasoning, and you can fork.

## Unacceptable behavior

- Harassment, threats, personal attacks, or discriminatory language.
- Publishing someone's private information without permission.
- Deliberately derailing issues or reviews.
- Submitting malicious code, hidden telemetry, or a dependency that exfiltrates
  data.
- Pressuring maintainers for unpaid work or for a particular roadmap decision.

## Scope

This applies to issues, pull requests, discussions, commit messages, and any
project space. It also applies when you represent the project elsewhere.

## Enforcement

Maintainers may edit or remove comments, close issues, reject contributions, or
block accounts. Enforcement is proportional: a correction first, then a warning,
then removal from the project space.

To report a conduct problem, contact the maintainer through the GitHub profile in
[AUTHORS](AUTHORS). Reports are handled privately. Do not open a public issue
about a person.

## Attribution

This is a project-specific policy, not a copy of a template. It is intentionally
short so it can be read in one sitting.
