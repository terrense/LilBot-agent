> 日期：2026-10-29 · 分支 `dev/nayang` · 对应计划：[02-七天优化计划.md](02-七天优化计划.md) 的 Day 4（差距 P5）

## 1. 一页结论

| 指标（本仓库，中位数） | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| `grep` 搜不存在的字符串 | 1,434 ms（Day 0 测到 1,739 ms，波动 1.1–3.2 s） | **54 ms** | **~26×** |
| `grep "def run_turn"` | 1,175 ms | ~55 ms | ~21× |
| `glob **/*.py` | 1,084 ms，返回 **1,793 行（其中 1,682 行是 `.venv`）**，95K 字符 ≈ 24K token | **9 ms，113 行** | 120×，输出缩小 94% |
| `list_dir`（深度 1） | 211 ms | 6 ms | 35× |
| `file_search` | 197 ms | 10 ms | 20× |
| `project_map` | 206 ms | 12 ms | 17× |
| 符号类工具的文件枚举 `_iter_source_files` | 883 ms | 8 ms | 110× |
| 真实任务：MiniMax-M3 “找 jittered_backoff + 数 .py 文件” | 19 步 / 26.5 s | **2 步 / 5.8 s** | 模型不再绕路 |

顺手修掉的 **4 个正确性 bug**：

1. `glob` 不过滤 `.venv`，一次把 2.4 万 token 的无关路径塞给模型。
2. `grep` 的 `path` 指向单个文件时**永远返回“无匹配”**（`Path.rglob` 在文件上什么也不产出）。
3. `grep` 会读 PNG 等二进制文件（本仓库 4.6 MB 图片），并在乱码里“匹配”到结果。
4. `.gitignore` 完全不被尊重（`*.egg-info`、`.env`、`*.log` 都会被搜索）。

全量测试：481 → **509 passed**（新增 28 个，7 skipped 中有 1 个是 Windows 上无法创建符号链接的用例）。

## 2. 背景与目标

计划目标：仓库根目录 grep 从 ~1.7 s 降到 **< 150 ms**（不装 ripgrep 的情况下），并且 `.venv` 的内容不再出现在结果里。

agent 的每一次 grep / glob 都是**同步阻塞**在主循环里的：模型发起一次搜索，用户就要多等 1–3 秒；一个排查任务常常要连续搜 5–10 次。更糟的是 glob 的噪声输出会直接进入上下文，既费 token 又干扰模型判断。

## 3. 排查过程：先量，再猜

### 3.1 第一步：给每个工具单独测基线

不只测 grep，把**所有遍历目录的工具**都测一遍，每个跑 3 次取中位数（单次波动可达 2 倍，见坑 #10）：

```
grep no-match       1434 ms
glob **/*.py        1084 ms   → 输出 1793 行，1682 行含 .venv   ← 正确性问题！
list_dir depth=1     211 ms   ← 只看一层，为什么要 200ms？
iter_source_files    883 ms
```

`list_dir` 只列一层却要 200 ms，这说明**它也在遍历整棵树**。打开代码一看，`base.rglob("*")` 一共出现在 **8 处**，每个工具各写一份遍历。

### 3.2 第二步：拆解 grep 的时间

直觉是“`.venv` 文件多，读得慢”。但拆开来量，结论完全不同：

| 步骤 | 耗时 |
|---|---|
| `rglob("*")` 列出全部 4,557 项 | 195 ms |
| **逐项 `is_file()` + `_is_noisy_path()` 过滤** | **831 ms** ← 真正的大头 |
| 读取保留下来的 183 个文件 | 175 ms（其中 3 张 PNG 共 4.6 MB） |
| 对比：`os.walk` 先剪枝再进入，得到同样 183 个文件 | **7 ms** |

**根因**：`Path.is_file()` 每次都要发一个 `stat` 系统调用。这台机器上装有透明加密 + 杀毒的文件过滤驱动，每个 `stat` 约 0.18 ms，4,557 项就是 0.8 秒——而其中 4,000 多项是 `.venv` 里**本来就要丢掉**的。`os.scandir` 返回的 `DirEntry` 在 Windows 上直接从目录列表里带出“是不是目录”，不需要额外 `stat`。

### 3.3 第三步：修完后再拆一次——瓶颈转移了

换成剪枝遍历后 grep 降到 ~145 ms，已经达标。但再拆一次：

```
walk 178 files: 9 ms | read 175 files: 125 ms (0.72 ms/file) | regex: 11 ms
```

瓶颈从“遍历”转移到了“**打开文件**”——每个文件 0.72 ms，几乎都耗在内核里的过滤驱动上。这段时间线程在等 I/O，**GIL 是释放的**，所以多线程能真正并行：

```
sequential  120 ms
4 threads    37 ms
8 threads    30 ms
```

这就是 ripgrep 快的原因之一（并行读），我们用 8 个线程拿到了同样的效果，grep 最终 54 ms。

### 3.4 第四步：真实任务里发现“工具输出形状”问题

用 MiniMax 真跑一个任务时，模型调用 `glob lilbot/**/*.py` 想**数文件个数**，但 glob 只返回列表、不返回数量，于是模型去试 shell（被拒）、试 Python（被拒），最后**按子目录 glob 了 14 次再相加**——19 步、26 秒。给 glob 输出末尾加一行 `(66 matches)` 后，同样的任务 2 步完成。

> 教训：对 agent 来说，工具输出的“形状”直接决定模型的行为和 token 开销，和工具本身的速度一样重要。

## 5. 优化策略（以及为什么这样选）

### S1 · 一个统一的剪枝遍历器 `lilbot/sandbox/walk.py`

- 用 `os.scandir` 递归，`DirEntry.is_dir(follow_symlinks=False)` 不额外 `stat`。
- **进入目录之前**就判断是否噪声目录，噪声目录连列表都不列。
- 每层按名字排序后深度优先，**输出顺序与 `sorted(base.rglob("*"))` 完全一致**（Windows 上不区分大小写），所以旧工具的输出顺序不变——这是能放心替换 8 处调用的前提。
- 符号链接目录：列出但不进入（和 `rglob` 行为一致，也防止循环和越出工作区）。
- 噪声判断增加后缀规则：`*.egg-info`。
- 搜索起点本身是噪声目录时照样遍历：`grep path=".venv"` 仍然可用——只剪“下面遇到的”，不剪“用户点名的”。

> 为什么放在 `sandbox/` 而不是计划里写的 `tools/search_backend.py`：`Sandbox.glob/grep` 也要用它，而 `sandbox` 不应该反向依赖 `tools`。`NOISY_DIRS` 也搬了过来，`builtin.py` 里保留同名导出，旧引用不受影响。

### S2 · `.gitignore` 的安全子集

- 支持：名字通配（`*.log`、`.env`）、目录规则（`build/`）、根锚定路径（`/tmp/`、含 `/` 的规则）、`**/` 前缀。
- **不支持**：否定规则（`!keep.log`）、子目录里的 `.gitignore`。遇到否定规则直接跳过——这样最坏情况是“某个被重新包含的文件看不到”，**不会**出现“被忽略的文件被搜出来”。宁可少，不可多。
- 按 `(mtime, size)` 缓存解析结果，`.gitignore` 改了自动失效。
- **只对“搜索类”工具生效**（grep / glob / file_search / project_map / 符号枚举）。`list_dir` 是“看目录里有什么”，仍然显示被忽略的文件（如 `run.log`），只剪噪声目录。

### S3 · 跳过二进制和超大文件

- 已知二进制后缀（图片、压缩包、模型权重、数据库……）**根本不打开**。
- 其他文件读前 8 KB，含 NUL 字节就当二进制——这是 git 判断二进制的同一条规则。
- 超过 2 MB 的文件跳过（压缩过的 JS、日志、数据文件，搜了也没法给模型看）。
- grep 的 metadata 新增 `files_scanned` / `files_skipped`，跳过了多少可观测。

### S4 · 兼容 `rglob` 语义的 glob 翻译

`fnmatch` 不能直接用：它的 `*` 会跨越 `/`。自己把 glob 翻译成正则：

| glob | 正则 | 说明 |
|---|---|---|
| `*` | `[^/]*` | 不跨目录 |
| `?` | `[^/]` | |
| `**/` | `(?:.*/)?` | 跨任意层，含 0 层 |
| `[!x]` | `[^x]` | |
| （隐式前缀） | `(?:.*/)?` | `rglob(p)` 等价于在任意深度匹配 `p` |

另外两条兼容细节：Windows 上不区分大小写（pathlib 在 Windows 上就是这样）；模式以 `**` 结尾时**只匹配目录**（Python 3.11 的 `rglob("**")` 行为，3.13 改了，见坑 #6）。

### S5 · 并行读文件

`read_texts()` 用 8 个线程读、`executor.map` 保持输入顺序；**按 32 个一批提交**，调用方因 `max_results` 提前停止时最多浪费一批（`executor.map` 一次性提交全部任务，不分批的话找到第一条结果后还会把剩下几百个文件读完）。

### S6 · glob 返回数量

输出末尾加 `(N matches)`，metadata 加 `count` / `paths`。

### 考虑过但**没有做**的

| 方案 | 为什么不做 |
|---|---|
| **ripgrep 优先**（Hermes 的做法） | 这台机器没装 rg，代码写了也无法端到端验证；纯 Python 已经 54 ms，远低于 150 ms 目标；引入外部程序还会带来 `.gitignore` 语义差异、Windows 路径格式、编码处理等新的不一致。**等出现真正的大仓库（几万文件）再加，并配上“有 rg / 无 rg 结果一致”的对照测试。** |
| 整个文件先 `re.search` 一次，命中了再逐行 | 语义不等价：`MULTILINE` 下 `$` 只在 `\n` 前匹配，而 Windows 文件是 `\r\n`，逐行搜能命中的 `foo$` 整文件搜会漏；`\A` / `\Z` 也不一样。省 10 ms 不值得冒漏结果的风险（见坑 #8）。 |
| 跨调用缓存文件内容 | 需要处理失效和内存上限；当前 54 ms 已足够，收益不明显。 |
| 给 grep / glob 加 `include_ignored` 参数 | 会改变工具 schema（影响提示缓存）；需要时可以用 `path=` 直接点名目录。 |

## 6. 代码走读

建议按这个顺序读：

### 6.1 [`lilbot/sandbox/walk.py`](../../lilbot/sandbox/walk.py)（新文件，核心）

1. **常量**（第 28–47 行）：`NOISY_DIRS`、`NOISY_DIR_SUFFIXES`、`BINARY_SUFFIXES`、`MAX_SEARCH_FILE_BYTES`。想调整“哪些不搜”只改这里。
2. **`walk()`（第 132 行）** —— 最重要的 50 行：
   ```python
   def scan(directory, rel_prefix, depth):
       with os.scandir(directory) as it:
           entries = sorted(it, key=lambda e: _sort_key(e.name))   # 每层排序 → 全局顺序 = sorted(rglob)
       for entry in entries:
           is_dir = entry.is_dir(follow_symlinks=False)             # 不额外 stat
           if is_dir and is_noisy_dir(entry.name):
               continue                                             # ← 剪枝：根本不进入
           if ignore is not None and ignore.ignored(...):
               continue                                             # ← .gitignore
           if not is_dir or include_dirs:
               yield WalkEntry(path, rel, is_dir, depth)
           if is_dir and not entry.is_symlink() and (max_depth is None or depth < max_depth):
               yield from scan(path, rel + "/", depth + 1)          # 深度优先
   ```
   注意 `continue` 发生在递归**之前**——这就是“先剪枝再遍历”。
3. **`IgnoreRules`（第 75 行）**：解析 `.gitignore`，`ignored(name, root_rel, is_dir)` 决定忽略与否。锚定规则用“相对仓库根”的路径匹配，所以从子目录开始遍历也能正确应用（有专门的测试）。
4. **`read_text_for_search()`（第 192 行）**：后缀 → 大小 → 读字节 → NUL 嗅探 → 解码，四道关。
5. **`read_texts()`（第 214 行）**：分批并行读，`islice` 每次取 32 个。
6. **`glob_to_regex()` / `glob_matches_dirs_only()`（第 235–240 行起）**：S4 的翻译表。

## 7. 数据流

### 优化前：grep 一次

```
模型: grep("needle")
  └─ _grep
       └─ Path(".").rglob("*")             列出 4,557 项（含 .venv 4,000+）       195 ms
            └─ 逐项 is_file() → stat         4,557 次系统调用                      831 ms
            └─ _is_noisy_path() 丢掉 .venv
            └─ read_text(errors="ignore")    183 个文件，含 4.6 MB PNG（串行）      175 ms
                 └─ 逐行 re.search           可能在 PNG 乱码里“命中”
  └─ ToolResult → registry（脱敏 / 截断）→ 模型
                                                                     合计 ≈ 1.2–3 s
```

### 优化后：grep 一次

```
模型: grep("needle")
  └─ _grep
       ├─ path 是文件？ ──是──> [这个文件]
       └─ 否 ─> walk(base, respect_gitignore=True)                                    9 ms
                 ├─ os.scandir（类型来自目录列表，无 stat）
                 ├─ 噪声目录 / .egg-info → 不进入
                 └─ .gitignore 命中（.env, *.log, /tmp/）→ 跳过
            └─ candidates()：按 glob 参数过滤路径
            └─ read_texts()：8 线程，每批 32 个，保持顺序                              ~30 ms
                 └─ read_text_for_search：二进制后缀 / >2MB / NUL → None（计入 skipped）
            └─ 逐行 re.search，满 max_results 即停（最多多读一批）                      ~11 ms
  └─ ToolResult(matches, files_scanned, files_skipped) → registry → 模型
                                                                     合计 ≈ 54 ms
```

### 依赖关系

```
tools/builtin.py ──┐
                   ├──> sandbox/walk.py  (walk / iter_files / read_texts / glob_to_regex / IgnoreRules)
sandbox/workspace.py ┘          │
                                └──> 只依赖标准库：os, re, fnmatch, concurrent.futures
```

## 11. 以后要避免的坑

1. **在 Windows 上对大量路径调用 `is_file()` / `is_dir()` / `stat()`**。每次都是系统调用，有杀毒或加密过滤驱动时约 0.2 ms 一次。用 `os.scandir` 的 `DirEntry`，它在 Windows 上把类型信息随目录列表一起带回来。
2. **“先遍历、后过滤”**。`rglob("*")` 再 `if noisy: continue` 意味着你仍然付出了遍历噪声目录的全部代价。剪枝必须发生在**进入目录之前**（`os.walk` 里原地修改 `dirnames`，或自己递归时不递归）。
3. **`sorted(path.rglob(...))`**。`sorted` 会先把整棵树全部读进内存才返回第一个结果，`limit` 也救不了。需要有序就每层排序再深度优先。
4. **`Path.rglob` 在文件上返回空**。任何接受 `path` 参数的搜索工具都要单独处理“path 是文件”的情况。
5. **测试里写死路径顺序**。Windows 上 `Path` 排序不区分大小写（`README.md` 排在 `pkg/` 后面），Linux 上区分。要么用集合比较，要么用同一个排序键生成期望值。
6. **pathlib 的 `**` 语义随 Python 版本变化**。3.11/3.12 的 `rglob("**")` 只返回目录，3.13 开始也返回文件。自己实现 glob 时要明确对齐哪个版本，并写对照测试。
7. **把 `fnmatch` 当 glob 用**。`fnmatch` 的 `*` 会匹配 `/`，`fnmatch("a/b/c.py", "*.py")` 为真，而 glob 里 `*.py` 只匹配一层。
8. **“整文件预搜一次再逐行”的优化**。`re.MULTILINE` 的 `$` 只认 `\n`，CRLF 文件里 `foo$` 会漏；`\A`、`\Z`、后行断言也和逐行语义不同。凡是改变匹配范围的优化，都要先证明语义等价。
9. **`errors="ignore"` 读二进制文件**。不会报错，但会产出一堆乱码并“命中”搜索词。先按后缀和 NUL 字节排除。
10. **只跑一次的基准测试**。同一个 grep 在这台机器上测到过 1.1 s、1.7 s、3.2 s。至少 3 次取中位数，并同时记录**输出条数**，防止“变快了但结果变错了”。
11. **Windows 上重定向 Python 的 stdout**。默认是 GBK，`> out.json` 再用 UTF-8 读会报错。设置 `PYTHONIOENCODING=utf-8`。
12. **`executor.map` 一次提交全部任务**。调用方提前 `break` 时，剩下的任务照样会执行完。需要“可以提前停”的并行就分批提交。
13. **只看工具速度，不看工具输出的形状**。glob 不给数量，模型就多花 17 步。设计 agent 工具时要问：模型拿到这个输出，下一步需要什么？
14. **假设瓶颈**。直觉是“文件多所以读得慢”，实测是“`stat` 太多”；修完之后瓶颈又变成“打开文件”。每次优化后都要重新拆解。

## 12. 需要记住的知识点

- **`os.scandir` vs `Path.rglob` vs `os.walk`**：`scandir` 是最底层的，返回带缓存类型信息的 `DirEntry`；`os.walk` 基于 `scandir`，并允许原地修改 `dirnames` 来剪枝；`Path.rglob`（3.11）也基于 `scandir`，但**无法剪枝**，而且调用方拿到的是 `Path`，再调 `is_file()` 就是一次新的 `stat`。
- **剪枝的复杂度意义**：先遍历后过滤的代价是 O(整棵树)，先剪枝是 O(保留部分)。本仓库保留部分只占 4%，所以差了 100 倍。
- **GIL 与 I/O**：Python 线程在等待文件 / 网络 I/O 时会释放 GIL，所以 I/O 密集任务用线程池就能真并行（120 ms → 30 ms）；CPU 密集任务（比如正则本身）则不行。
- **ripgrep 为什么快**：并行遍历和读取、默认尊重 `.gitignore`、跳过二进制、用 SIMD 做字面量搜索、正则引擎有线性时间保证。我们这次复刻了前三条。
- **git 判断二进制文件的规则**：前 8,000 字节里有没有 NUL 字节。
- **glob → 正则的翻译**：`*` → `[^/]*`，`**/` → `(?:.*/)?`，`?` → `[^/]`；`rglob(p)` 等价于在任意深度匹配 `p`。
- **Windows 文件系统过滤驱动**：杀毒、透明加密、备份软件都会挂在文件打开 / `stat` 路径上，让每次系统调用变贵几十倍。在这类机器上“少打开、少 stat”比“少读字节”更重要。
- **Amdahl 定律在实践中的样子**：把最大的那块（831 ms）干掉以后，原来不起眼的部分（打开文件 125 ms）就成了新的大头。优化是一轮一轮“测 → 拆 → 改 → 再测”。
- **agent 工具设计原则**：输出要“够用且最少”——去掉噪声（`.venv`），补上模型下一步需要的信息（数量），并在 metadata 里留下可观测数据（扫描/跳过了多少文件）。
